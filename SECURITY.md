# Security policy

## Reporting a vulnerability

Until a public security contact is created at release, report suspected
vulnerabilities privately to the repository owner through GitHub’s private
security reporting feature or a private GitHub message. Do not open a public
issue for a vulnerability involving tenant isolation, redaction, API-key
handling, retention deletion, or broker/storage behavior.

Include a minimal synthetic reproduction, affected revision, impact, and any
suggested mitigation. Never include a real credential, raw telemetry, or
customer data in a report.

## Supported state

The project is a private, local-development prototype until all documented
release gates pass. No version is currently represented as production-ready.
