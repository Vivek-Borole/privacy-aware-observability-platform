# v0.2.0 local release verification

**Scope:** local-only synthetic telemetry. No customer data, production
credential, paid cloud service, or hosted workload was used.

## Native OTLP benchmark

The release workload ran on 2026-09-02 with
`PAOP_SKIP_BUILD=1 bash scripts/run-benchmark.sh` on a MacBook Pro (Mac15,6),
Apple M3 Pro with 11 host cores and 18 GB memory. Colima exposed six CPUs and
8,306,724,864 bytes of memory to Docker. Software versions were macOS 26.5.2,
Go 1.26.6, Node 22.23.1, Docker Engine 29.5.2, and Docker Compose 5.5.0.

The emitter drove official OTLP/HTTP protobuf in 200-span batches at a nominal
5,100 spans/second. The 2% drive margin did not lower the acceptance gate:
actual accepted throughput still had to be at least 5,000 spans/second.

| Gate | Measured result | Result |
| --- | ---: | --- |
| Duration | 600.016 seconds | complete |
| Spans sent / accepted | 3,060,000 / 3,060,000 | pass |
| Failed spans | 0 | pass |
| Actual accepted throughput | 5,099.861 spans/second | pass (minimum 5,000) |
| Ingest request p50 / p95 / p99 | 24.464 / 687.592 / 1,184.780 ms | measured |
| Trace lookup p50 / p95 / p99 | 14.241 / 28.511 / 78.165 ms | pass (p95 maximum 3,000 ms) |

The local PostgreSQL profile declared a 512 MB shared buffer, 30-minute
checkpoint interval, and 16 GB maximum WAL size. This avoids the container
image's small default WAL ceiling turning the experiment into repeated forced
checkpoints. These are documented harness settings, not universal production
tuning. A post-run snapshot showed PostgreSQL using about 916 MiB, ClickHouse
1.34 GiB, Redpanda 247 MiB, and each Go service below 10 MiB; peak resource use
was not sampled, so no peak-resource claim is made.

An earlier run with the image's default WAL ceiling failed (495 spans failed,
4,722.772 accepted spans/second) and was rejected by the validator. Failed raw
artifacts remain local and are not represented as release evidence.

## Compatibility, recovery, and privacy gates

Release verification includes:

- native OTLP/HTTP protobuf trace and log tests plus authenticated OTLP/gRPC;
- official OpenTelemetry Collector forwarding through the redaction-first
  gateway;
- current/previous envelope migration tests and future-version rejection into
  a payload-free dead-letter record;
- 30-second policy refresh with compile-before-activate and last-valid fallback;
- two gateway, query, tailer, and persistence replicas in local kind, followed
  by rolling restarts and a post-roll sanitized trace lookup;
- Compose integration, consumer/broker/storage recovery, duplicate-delivery,
  bounded backpressure, retention, tenant-isolation, and cross-store privacy
  scans;
- Go race tests, TypeScript checks/builds, OpenAPI compatibility, Helm lint and
  render, dependency audit, secret scan, and benchmark schema validation.

The raw benchmark JSON, lookup JSON, and environment capture are attached to
the GitHub release only after the privacy scan. The checked-in screenshots and
short demo remain synthetic-only and were reviewed under `docs/demo-script.md`.

## Limitations

This result is single-region local evidence under a synthetic workload.
Stateful kind dependencies are single-node. The system uses at-least-once
delivery with deterministic event identity and a persistence ledger; it does
not claim global exactly-once semantics, hosted production operation,
production customers, multi-region availability, or performance beyond the
workload above. OTLP metrics ingestion remains outside v0.2.0.
